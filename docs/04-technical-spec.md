# 04: Technical spec (Next.js)

**Goals:**
- Every page is static HTML containing its title, canonical, JSON-LD, all content **and the default calculator result**.
- One small client island per tool.
- LCP is text, never an image.
- Zero third-party scripts until they're needed.

**Versions:** use the latest stable releases at build time (verify), and pin them in `package.json`.

## 1. Stack
| Layer | Choice | Notes |
|---|---|---|
| Framework | **Next.js, App Router**, TypeScript `strict` | `output: 'export'` (static), so it's host-agnostic |
| Styling | Tailwind CSS (latest), CSS variables for light/dark | No UI kit runtime. Small hand-built components (Radix primitives only if needed, e.g. a dialog) |
| Content | Tools: typed TS modules. Guides: MDX (`@next/mdx`) | Validated at build with `zod` |
| Calculators | Pure functions in `lib/calculators/*.ts` | Run on the server for the default result and on the client for live updates |
| Tests | Vitest (unit, schema, content), Playwright (e2e), Lighthouse CI | All run in CI before every deploy |
| Fonts | System font stack (zero bytes). A `next/font` Geist subset was tried and measured +1.1 s LCP on throttled mobile (2026-10-11 [M]), so it was removed | No layout shift, no font bytes |
| Analytics | GA4 through `next/script` (`lazyOnload`) with Consent Mode, **or** a cookieless analytics service at launch | The playbook needs GA4 for the AI-referral channel; add it with the consent banner |
| Ads | **None until the playbook §0.2 gate.** An `AdSlot` component exists but renders nothing unless `NEXT_PUBLIC_ADS_ENABLED=true` | Slot heights are reserved when enabled |

## 2. `next.config` essentials
```ts
// next.config.ts
const config = {
  output: 'export',
  trailingSlash: true,            // URLs end with "/" (e.g. /diy/gravel-calculator/)
  images: { unoptimized: true },  // static export
  reactStrictMode: true,
  pageExtensions: ['ts', 'tsx', 'mdx'],
};
export default config;
```
- **Redirects and headers live in the host config:**
  - Cloudflare Pages: `public/_redirects` and `public/_headers`.
  - Vercel: `vercel.json`.
- **Security headers and CSP:** follow [`security/02-headers-csp.md`](../security/02-headers-csp.md), which has the exact `_headers` file.
  - A static export ignores `headers()` in `next.config` and can't use nonces.
  - So `script-src` needs `'unsafe-inline'` unless the SRI test in security/02 §4 passes.
  - Third-party origins are added phase by phase (analytics, consent banner, ads).
- **Caching:** HTML `max-age=0, must-revalidate`; `/_next/static/*` immutable for 1 year.

## 4. Content model (validated with zod at build)
```ts
type Source = { title: string; url: string; publisher: string; accessed: string /* YYYY-MM-DD */ };
type Faq = { q: string; a: string };                 // plain-text answer, also used in JSON-LD
type Tool = {
  slug: string; hub: HubSlug; name: string;          // "Gravel Calculator"
  primaryKeyword: string; secondaryKeywords: string[];
  title: string;        // ≤ 60 chars
  description: string;  // ≤ 155 chars
  h1: string; directAnswer: string;                  // 40–60 words, plain text with the formula
  calculator: string;                                // key into lib/calculators
  defaults: Record<string, number | string>;
  presets?: { label: string; values: Record<string, number | string> }[];
  faqs: Faq[];                                       // 5–8
  sources: Source[];                                 // ≥ 2 for any page with constants
  guides: string[];                                  // guide slugs, as the keyword map in docs/02 sets (0–2 at launch)
  related: string[];                                 // 3–6 tool slugs, same hub first
  disclaimer?: string;
  published: string; updated: string; reviewed?: { by: string; credential: string; date: string }; // only if real
  batch: 1 | 2 | 3;
};
```
Build fails if:
- a required field is missing;
- a title exceeds 60 characters or a description 155;
- a FAQ answer is empty;
- `reviewed` is set without `credential`.

## 5. Tool page rendering
1. `[hub]/[tool]/page.tsx` is a **server component**. Set `generateStaticParams()` from `content/tools/*` where `batch <= CURRENT_BATCH`, with `dynamicParams = false`.
2. It calls `lib/calculators/<slug>(defaults)` **at build** and renders the result into the HTML. Crawlers and AI bots see real numbers.
3. `CalculatorShell` (`'use client'`) hydrates with the same defaults:
   - updates on input with `startTransition`;
   - no network calls;
   - **no `history.pushState`/`replaceState` on input.**
4. The **"Copy link"** button writes the current inputs as query params to the clipboard. On load, the client applies query params after hydration. The canonical always stays the base URL.
5. **Units:** a global imperial/metric toggle (context + `localStorage` in try/catch). Default is imperial (US).
6. **Content order** follows docs/05 §1. The result card comes first on mobile and stays sticky on narrow screens.

## 6. Build-time checks (`scripts/check-content.ts`, run in CI)
- **Keyword map:**
  - every primary keyword is unique;
  - every secondary keyword belongs to exactly one URL;
  - every tool's `primaryKeyword` matches the registry.
- **Title and H1 similarity:** token Jaccard > 0.8 between any two pages fails the build.
- **Guide titles and H1s must not contain "calculator".**
- **Orphans:** every published page has **≥ 3 internal inbound links** and appears in the sitemap. Pages are ≤ 3 clicks from home.
- **Lengths:** titles ≤ 60, descriptions ≤ 155, `directAnswer` 40–60 words, 5–8 FAQs.
- **Data provenance:** every `data/*.json` has `source`, `source_url`, `retrieved` and `license` (security SEC-CODE-16).
- **Security bans** (security/01, security/02):
  - no `<script>`, `<iframe>`, `<object>`, `<embed>`, `on*=` handlers or `javascript:` in `.mdx` (SEC-CODE-15);
  - `public/_headers` stays within Cloudflare's limits of 100 rules and 2,000 characters per line (SEC-HDR-08).
- **No placeholders in published pages:** `BRAND`, `SITE_URL`, `[Your name]`, `TODO`, "lorem", "coming soon".

## 7. SEO infrastructure
- **Metadata** (`generateMetadata`):
  - title, description;
  - `alternates.canonical` (absolute, trailing slash);
  - `robots: index,follow` (noindex for any preview build);
  - Open Graph and Twitter (static hub OG image).
- **`sitemap.ts`:** every published URL, with `lastModified` = content `updated`. Submit it to GSC and Bing Webmaster.
- **`robots.ts`:**
  - allow all, including Googlebot, Bingbot, OAI-SearchBot, PerplexityBot and Claude-SearchBot;
  - training bots (GPTBot, ClaudeBot, Google-Extended) allowed at launch (playbook §4);
  - `Sitemap:` line.
- **IndexNow:** key file in `public/`, and `scripts/indexnow.ts` posts the changed URLs after each deploy.
- **Internal links:**
  - breadcrumb on every page;
  - tool ↔ its guides (both ways);
  - 3–6 related tools;
  - hub lists all its tools;
  - home links every hub.
- **`llms.txt`:** deferred (playbook §12).

**Guide page:**
- `Article` with `headline`, `author` (Person `@id`), `datePublished`, `dateModified`, `mainEntityOfPage`, and `about: {"@id": "<tool URL>#app"}`;
- `BreadcrumbList` (Home › Hub › Tool › Guide);
- optional `FAQPage`.

**Hub page:** `CollectionPage` + `ItemList` (its tools) + `BreadcrumbList`.

**Home page:** `Organization` + `WebSite`.

**About page** (added 2026-10-10):
- `AboutPage` with `mainEntity` → the `Person` `@id`;
- the `Person` carries your real `name`, `url`, and `sameAs` links to your real public profiles (only ones that exist);
- `BreadcrumbList`.

**Contact page:** `ContactPage` + `BreadcrumbList`. The email stays a visible `mailto:` link. Don't add `email` to the schema; it attracts spam scrapers.

**Never include:** `aggregateRating` or `review` (no self-made ratings), `HowTo`, or `SearchAction` (unless real site search exists).

**FAQPage text must equal the visible FAQ text.** A unit test enforces this. FAQ rich results stopped on 2026-05-07 [U, verify], but the markup is harmless and machine-readable.

## 8. Performance budgets (CI-enforced with Lighthouse CI, mobile)
| Metric | Lab target | Field target (p75) |
|---|---|---|
| LCP | ≤ 1.8 s | ≤ 2.5 s |
| CLS | ≤ 0.05 | ≤ 0.1 |
| TBT / INP | TBT ≤ 150 ms | INP ≤ 200 ms |
| First-load JS per tool route | ≤ 70 KB gzip | — |
| CSS | ≤ 20 KB gzip | — |

- No hero images. The LCP element is the H1 or the result card.
- **Known gap (2026-10-11 [M]):** first-load JS is about 190 KB gzip on every route (Next.js and React runtime), against the 70 KB budget. It is the biggest remaining LCP and INP cost, and it predates the redesign. Options are tracked in docs/08.
- Fonts don't shift layout (`font-display: swap` + metric fallback, or the system stack).
- Every client component except `CalculatorShell` and `UnitToggle` is a server component.
- Analytics loads `lazyOnload`. Future ad slots get fixed `min-height` and never sit inside the inputs or result.

## 9. Accessibility (WCAG 2.2 AA basics)
- Every input has a `<label>`.
- Numeric inputs use `inputmode="decimal"` at font-size ≥ 16 px. Touch targets are ≥ 44 px.
- Errors are announced through `aria-live="polite"` on the result region.
- Visible focus, contrast ≥ 4.5:1, a skip link, and full keyboard operation (including the bowling keypad).

## 12. Deploy
1. `npm run verify` runs the repo checks, audit, lint, typecheck, unit tests, build (+ `flatten-segments` + `check-out`) and e2e. `npm run build` alone produces `out/`. Cloudflare build settings: build command `npm run build`, output `out`, env `NODE_VERSION=22.23.3`.
2. **Cloudflare Pages** (decided 2026-10-10; build output `out/`), connected to the GitHub repo (security SEC-SEC-04). Custom domain `calculatorporch.com` with HTTPS. `www.calculatorporch.com` → `https://calculatorporch.com/` through a single 301 (a Cloudflare redirect rule).
3. **After the first deploy:**
   - GSC Domain property + sitemap;
   - Bing Webmaster (import from GSC) + sitemap;
   - run `scripts/indexnow.ts`;
   - URL Inspection for the 8 tools.
4. **Every release:** update the `updated` dates only for real changes, and append to the `/methodology/` changelog.
